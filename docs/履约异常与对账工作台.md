# 履约异常与对账工作台

入口为彩云后台「中台管理 → 履约异常与对账」，路由 `/admin/fulfillment-workbench`。

## 日常处理

1. 选择企业。异常页显示该企业最新的 OA 审批驳回、应用交换失败、超过 15 分钟未确认的消息，以及账差、证据不完整和长期待同步记录。
2. 点击「追踪」，或输入合同 UUID 并选择「单据追踪」。页面显示 OA 审批、跨系统消息、ERP 订单和出入库单、WMS 作业单、MES 工单，以及相关重试记录。责任列显示应用，账据有本地操作成员时显示该成员 ID。
3. 核对异常原因。待 OA 审批、待 ERP 审核和待 WMS 作业由业务应用处理。遇到授权、主数据或状态冲突，先到责任应用处理。
4. 对尚未送达的发件或尚未确认的收件，点击「重试」。应用调度器处理原消息 UUID 和原始快照。确认以中台收到原发件或原收件 ACK 为准。操作员、原消息、执行应用、时间和结果记录在工作台。重复提交只保留一个排队任务。
5. 在「对账」核对双方证据。账差通过原业务单据、库存和结算流程处理。工作台提供证据、原因和重试入口。

## 对账口径

| 对账项 | 来源与匹配规则 |
| --- | --- |
| 出库、生产入库、销售退货入库 | 同一中台仓库请求 UUID。读取 WMS `receipt` / `issue` 流水和 ERP 实际过账流水，按中台仓库和物料比较有符号基本数量。WMS 同物料的多笔批次流水汇总至该请求。 |
| 应收、收款、退货冲减、退款 | 同一合同 UUID 和 ERP 投影版本。ERP 汇总实际应收条目、核销和退货退款条目，CRM 读取已保存的履约进度。对比币种、原始应收、已收款、退货冲减、净未收、应退款、已退款。 |
| 单边已过账 | 显示等待另一侧同步，超过 15 分钟进入异常页。若另一侧已驳回或取消，显示账差。 |
| 缺少物料绑定、库存流水或有效款项证据 | 显示证据不完整。账据展开区显示来源单号及采集时间。 |
| 双方同版本或均已过账 | 量、仓库或金额不一致时显示账差。CRM 版本落后时进入待同步。 |

## 部署与权限

1. 先发布彩云后台并执行常规迁移，加载工作台路由。
2. 为目标企业的 **CRM、ERP、WMS、MES** 四个应用实例分别添加企业级 scope。沿用各企业已开通的应用授权和现货、生产、退货配置。

   ```sh
   php artisan platform:integration <application-code> --enterprise=<enterprise-uuid> \
     --scope=fulfillment.observe --scope=fulfillment.retry
   ```

3. 发布四个接入应用。将指定企业 UUID 加入各项目的 `CAIYUN_FULFILLMENT_ENTERPRISES`，多个 UUID 使用逗号分隔。空值关闭工作台接入。刷新相应 Laravel 配置和常驻进程。保持原有 `stock:sync` 或 `stock:production-sync` 调度，并启用每分钟的 `stock:observe`。本机可手动触发 `php artisan stock:observe --enterprise=<本地企业或租户ID>`。OA 审批记录直接使用已有中台快照。
4. 为现有后台操作员授予对应企业权限。平台超级管理员沿用中台管理权限。普通后台账号默认无访问权。只读权限省略 `--retry` 即可，撤销使用 `--revoke`。

   ```sh
   php artisan platform:fulfillment-operator <enterprise-uuid> <admin-user-id> --retry
   ```

5. 先开通单个试点企业，核对至少一笔库存单与一笔款项单。需要暂停时，先从接入应用名单移除该企业，回收工作台 scope 和操作权限。已采集证据和原业务消息可保留。

## 中台接口

均使用现有 SAPI 应用签名。工作台接口还需企业级应用开通和对应 scope。

| 方法和路由 | 权限 | 用途 |
| --- | --- | --- |
| `POST /sapi/integration/fulfillment/reports` | `fulfillment.observe` | 企业 UUID、采集时间、主题及最多 50 条记录。主题为 `failure`、`inventory`、`finance`、`production`。库存、资金和生产证据依原消息绑定应用。 |
| `GET /sapi/integration/fulfillment/retries` | `fulfillment.retry` | 读取企业内分配给签名应用的原消息重试，按发送或接收方向筛选。接收需指定原消息类型。 |
| `POST /sapi/integration/fulfillment/retries/{uuid}/finish` | `fulfillment.retry` | 执行应用结束一次尝试。中台根据原消息和 ACK 判定结果。 |
| `GET /sapi/integration/messages` | 原有 `business.receive.<kind>` | 企业和类型筛选，新增可选 `uuid` 用于读取一条待确认原消息。 |

## 本机验收

使用独立 SQLite 副本和临时后台操作员。历史数据验证了 8 条库存对账和 5 条款项对账一致，另有一条 MES 完工记录和一条取消单据记录。

新建一笔已审批的现货合同，完成 WMS 拣货出库并暂停 ERP 同步。浏览器显示 WMS 已过账、ERP 单据已审核和对账待同步。页面提交重试后，运行 ERP 同步并再次运行重试，确认原消息摘要保持一致、WMS 与 ERP 各有一笔库存流水、ERP 只生成一笔应收。CRM 接收款项版本，库存与财务均显示一致，浏览器可查到操作员和已完成的重试审计。
