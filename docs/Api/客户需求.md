# 客户需求 API

客户可通过公开接口提交项目需求，提交后由管理员在 Admin 后台的“客户需求”模块中分配负责人并跟进。

## 提交客户需求

- 请求方式：`POST /api/customer-requirements`
- 认证方式：无需登录
- Content-Type：`application/json`
- 限流：同一来源每分钟最多 5 次

该接口需要携带《客户端信息》中约定的通用请求头，例如：

```text
X-Client-Type: web
X-App-Version: 1.0.0
X-App-Build: 10000
X-Platform: web
X-OS-Version: unknown
X-Device-ID: web-installation-id
X-Channel: official
```

### 请求参数

| 参数 | 类型 | 必填 | 限制 | 说明 |
| --- | --- | --- | --- | --- |
| `contact_name` | String | 否 | 最多 100 个字符 | 联系人姓名 |
| `contact_method` | String | 是 | 最多 255 个字符 | 电话、邮箱、微信或其他联系方式 |
| `organization` | String | 否 | 最多 255 个字符 | 公司或组织名称 |
| `requirement_type` | String | 是 | 见需求类型 | 客户需求类型 |
| `requirements` | String | 否 | 填写时为 10～10000 个字符 | 项目背景、功能范围和其他需求说明 |

需求类型取值：

| 值 | 含义 |
| --- | --- |
| `website-cms` | 官网 / CMS |
| `web-admin` | Web / 管理应用 |
| `mobile-app` | 移动应用 |
| `product-trial` | 产品试用 |
| `other` | 其他 |

请求示例：

```json
{
  "contact_name": "张三",
  "contact_method": "zhangsan@example.com",
  "organization": "彩云科技",
  "requirement_type": "web-admin",
  "requirements": "需要开发一套订单、库存和数据报表管理后台。"
}
```

### 成功响应

HTTP 状态码：`201 Created`

```json
{
  "code": 201,
  "data": {
    "id": 1001,
    "message": "需求已提交，我们会尽快与您联系。"
  },
  "meta": {
    "timestamp": 1785888000.123,
    "response_time": 0.012
  }
}
```

服务端会自动将新需求设置为“待跟进”，并记录提交 IP 和 User-Agent。公开接口不接受跟进状态、负责人或内部备注字段。

### 参数校验失败

参数缺失、需求类型不在允许范围内，或项目需求长度不符合要求时返回：

- HTTP 状态码：`422 Unprocessable Content`
- `errors`：按字段返回具体校验错误

```json
{
  "message": "The selected requirement type is invalid.",
  "errors": {
    "requirement_type": [
      "The selected requirement type is invalid."
    ]
  }
}
```

### 请求过于频繁

超过每分钟 5 次的限制时返回 HTTP `429 Too Many Requests`，前端应提示用户稍后重试，不能立即循环请求。

## Admin 跟进说明

管理员可以在 Admin 后台完成以下操作：

- 按需求类型、跟进状态和负责人筛选需求；
- 分配跟进负责人；
- 将状态更新为待跟进、已跟进、已完成或已关闭；
- 填写仅管理员可见的内部跟进备注；
- 修改状态、负责人或跟进备注时，系统自动更新最近跟进时间。
